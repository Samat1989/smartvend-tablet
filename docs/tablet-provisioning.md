# Выдача прав администратора планшету

Как сделать планшет киоском: приложение получает права **device owner**, после
чего Android отдаёт ему экран целиком — без шторки, без навигации, без выхода.

Без этих прав приложение работает, но защищено только «закреплением экрана»,
из которого покупатель выходит удержанием двух кнопок.

> Что именно даёт owner и что остаётся без него —
> [kiosk-lockdown.md](kiosk-lockdown.md), если он появится. Пока подробности
> здесь.

## Два условия, без которых ничего не выйдет

Их проверяет сам Android, и обойти их со стороны канала связи нельзя — ни по
USB, ни по Wi-Fi. Разница между ними в том, что первое лечится, а второе нет.

### Аккаунтов на планшете быть не должно

Ни одного — ни Google, ни любого другого. С аккаунтом `dpm set-device-owner`
отказывает всегда.

Лечится удалением: Настройки → Аккаунты. Если аккаунт удалить нельзя (например,
корпоративный) — только сброс к заводским с пропуском входа.

**Это самая частая причина отказа**, и мастер первичной настройки предлагает
войти в аккаунт несколько раз подряд. Пропускать нужно каждое такое
предложение.

### Первичная настройка не должна быть завершена — на Android 12 и новее

До Android 11 включительно проверялись только аккаунты, поэтому команда
проходила на уже настроенном планшете. С Android 12 добавилось требование,
чтобы устройство ещё не считалось настроенным, — а планшет в руках монтажника
настроен всегда.

Как отличить по ошибке: в трассировке видно, кто отказал.

| класс в трассировке | версия | что проверяется |
|---|---|---|
| `com.android.commands.dpm.Dpm` | Android 11 | только аккаунты |
| `DevicePolicyManagerServiceShellCommand` | Android 12+ | плюс завершённость настройки |

Обходится тем, что флаги завершённости — обычные системные настройки:

```bash
adb shell settings put secure user_setup_complete 0
adb shell settings put global device_provisioned 0
adb shell dpm set-device-owner kz.smartvend.m102_tester/kz.smartvend.m102_tester.KioskAdminReceiver
adb shell settings put secure user_setup_complete 1
adb shell settings put global device_provisioned 1
```

**Возвращать флаги обязательно.** Планшет, оставленный в состоянии «настройка не
закончена», при следующей загрузке запустит мастер заново — это хуже, чем
отсутствие прав. Приложение mmd_diag делает это в `finally` именно поэтому.

Ещё одно требование, которое встречается реже: пользователь на планшете должен
быть один. Второй пользователь блокирует выдачу так же, как аккаунт.

## Три способа выдать права

### Кабелем — самый надёжный

```bash
adb shell dpm set-device-owner kz.smartvend.m102_tester/kz.smartvend.m102_tester.KioskAdminReceiver
adb reboot
```

Перезагрузка не формальность: приложение читает свои права **один раз, в
`onCreate`**. Пока оно не запустится заново, планшет ведёт себя ровно как
непровизиненный — что читается как «ничего не произошло».

### С телефона по Wi-Fi — [apps/mmd_diag](../apps/mmd_diag/)

Для выездов, когда ноутбука нет. Телефон становится ADB-хостом: показывает QR
сопряжения, планшет читает его камерой, дальше приложение само скачивает APK,
ставит его и выдаёт права.

Подробности и подводные камни — в самом приложении, экран «Настройка планшета».
Главное, что нужно знать: **беспроводную отладку на планшете включает человек
руками**, и она не переживает перезагрузку. Android требует доказательства, что
провизионирующий держит устройство в руках, — это же и защищает чужие планшеты
от того же приёма.

### QR при первичной настройке

Шесть нажатий по первому экрану мастера, камера, `provisioning/device-owner-qr.png`.
Единственный способ, не требующий вообще ничего, кроме планшета, — но
**сейчас не работает**: мастер обрывается с «что-то пошло не так», и причину
установить не удалось, потому что на настроенном планшете попытку не повторить
без сброса.

Если браться снова: сбросить планшет, попытаться, и **не перезагружая** пройти
мастер до конца, включить отладку и снять `adb logcat -b all`. Буфер переживает
мастер настройки, но не перезагрузку.

## Если планшет заперся

Планшет с правами owner, но без привязки к аппарату, до версии 1.1.34 замыкался
сам на себе: витрины нет, значит вход в сервисное меню недоступен, значит не
выйти в Настройки. С 1.1.34 тот же жест — **10 нажатий за 5 секунд** — работает и
на экране привязки, по значку в шапке.

На планшете со старой сборкой выход один: привязать его к аппарату, попасть на
витрину и дальше как обычно.

## Ограничение по разрядности

В релизах выкладывается **только `armeabi-v7a`**. На 32-битном и на обычном
64-битном планшете он ставится, на **чисто 64-битном** — нет:
`INSTALL_FAILED_NO_MATCHING_ABIS`. То же ограничение у встроенного обновления.

У новой партии планшетов проверять до закупки:

```bash
adb shell getprop ro.product.cpu.abi
```

## Как снять права

```bash
adb shell dpm remove-active-admin kz.smartvend.m102_tester/kz.smartvend.m102_tester.KioskAdminReceiver
```

Работает **только для test-only приложений**, а «тестовость» записывается в
момент выдачи прав — пересобрать приложение задним числом не поможет. Для
обычной сборки остаются два пути: приложение снимает права само
(`clearDeviceOwnerApp`), либо заводской сброс.

Заводской сброс права снимает всегда, так что после него планшет придётся
провизионировать заново.
