# esp-serial — замок по USB-serial

Прошивка релейной платы для **микромаркета на планшете**: холодильник с
электрозамком вместо моторов. Планшет ведёт витрину, принимает оплату и после
неё подаёт одну команду — открыть дверь.

Общий замысел и роль планшета — в [docs/tablet-micromarket.md](../../docs/tablet-micromarket.md).

## Чем отличается от esp-relay

Сделана из [esp-relay](../esp-relay/) вычитанием. Оттуда убрано всё сетевое:
MQTT, Wi-Fi, GSM, provisioning-портал, OTA, обращения к Supabase.

Причина простая: в static-QR реле само узнавало об оплате — отсюда брокер,
креды и своя связь. Здесь об оплате знает планшет, а плата стоит ниже по
течению и делает то, что велено.

| | esp-relay | **esp-serial** |
|---|---|---|
| Как узнаёт об оплате | MQTT от брокера SmartVend | команда с планшета по USB |
| Сеть | Wi-Fi / GSM | нет |
| Настройка | portal + `device-provision` | нечего настраивать |
| Обновление | OTA с GitHub Releases | только кабелем |
| Драйвер реле | бистабильное, DIR IO2 + импульс IO16 | **тот же, без изменений** |
| Внешний watchdog | есть | **есть** |

Плата перестаёт быть сетевым узлом: у неё нет ни кредов, ни канала в интернет.
Плата за это — перепрошивка только при обслуживании, с кабелем.

## Протокол

Построчный текст, **115200 8N1**, ответ на каждую команду:

```
PING        -> PONG
OPEN <сек>  -> OK | ERR <причина>
VER         -> esp-serial 1.0.0
```

Причины отказа: `busy` — замок уже открыт; `range` — время вне 1…600;
`unknown` — команда не распознана; `toolong` — строка длиннее буфера.

Текстовый протокол выбран, чтобы плату можно было проверить из любой
терминалки, не имея планшета. Для одной команды разбор кадров ничего бы не дал.

**Время удержания передаётся в команде, а не хранится в прошивке.** У этой платы
нет OTA — значит настройка, которую захотят менять, обязана жить на планшете,
где её правят без визита к железу. Планшет держит её в `DeviceStorage`,
по умолчанию 20 секунд.

**`OK` означает «команда принята», а не «покупатель забрал товар».** Ответ
уходит сразу, удержание идёт в отдельной задаче. Так дверь закроется вовремя,
даже если USB моргнёт посреди удержания.

Повторный `OPEN` во время удержания получает `ERR busy` — таймер не
продлевается. Второй такой запрос означает либо двойное нажатие, либо две
продажи в гонке, и молча держать дверь открытой дольше — неверный ответ на оба.

## Светодиод

Единственная диагностика на плате без консоли — GPIO33, тот же пин, что
использовал esp-relay:

| картина | что значит |
|---|---|
| одна короткая вспышка раз в 2 с | прошивка работает, с платой никто не разговаривает |
| две быстрые вспышки и пауза | хост шлёт команды, связь живая |

Именно «хост говорит», а не «USB подключён»: увидеть второе прошивка не может.
USB держит мост CH340, а ESP получает от него обычный UART без всякого
состояния подключения. Зато трафик виден — и раз планшет пингует раз в 10
секунд, трафик и есть точный признак живой связи.

Окно молчания — 30 секунд, втрое больше периода пинга: одна потерянная строка
не должна переключать картину.

Отметка ставится на **любую** принятую строку, даже на ту, что будет отвергнута:
искажённая команда всё равно доказывает, что на том конце кто-то есть, а
светодиод сообщает именно это.

## Консоль отключена намеренно

UART0 здесь — канал команд, а не лог. Любая строка, которую напечатал бы
фреймворк, попала бы в разборщик планшета и была бы принята за ответ. Поэтому в
`sdkconfig.defaults` заглушены и загрузчик, и логи приложения.

Отлаживать — по ответам на команды. Если нужен лог, выводите его на другой UART,
не на нулевой.

## Сборка и прошивка

```bash
# в окружении ESP-IDF (export.ps1 / get_idf)
cd firmware/esp-serial
idf.py set-target esp32
idf.py -p COM9 build flash
```

> ⚠️ Прошивка **перезапишет** то, что стоит на плате. Полный бэкап штатной
> прошивки SmartVend снят: `esp32_dump/flash_full.bin`. Откат:
> `python -m esptool --port COM9 write-flash 0 esp32_dump/flash_full.bin`

## Проверка без планшета

Открыть COM-порт на 115200 любой терминалкой и слать строки:

```
PING          ждём PONG — связь есть
VER           версия прошивки
OPEN 3        ждём OK, реле щёлкает, через 3 секунды щёлкает обратно
OPEN 3        сразу после предыдущей — ждём ERR busy
OPEN 0        ждём ERR range
HELLO         ждём ERR unknown
```

Если `PING` молчит — проверьте скорость порта и что плата не осталась в режиме
загрузки.

## Что проверить на стенде

1. Реле щёлкает в обе стороны, замок открывается и закрывается.
2. Просадка питания при срабатывании замка не роняет USB-связь с планшетом —
   замок берёт 1–2 А, и это самая частая причина «команда прошла, а плата
   отвалилась».
3. Снять питание при открытом замке и подать снова: реле **бистабильное**, оно
   держит положение без тока, поэтому прошивка на старте принудительно
   защёлкивает его закрытым. Без этого дверь осталась бы открытой.
