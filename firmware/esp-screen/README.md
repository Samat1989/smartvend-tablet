# esp-screen — микромаркет с экраном на автомате

Третий тип продающего устройства: холодильник с электрозамком, где покупатель
выбирает товар **на экране самого автомата**, а телефон нужен только чтобы
отсканировать QR и заплатить.

Замысел, экраны, отказы и контракт с бэкендом —
[docs/esp-screen-micromarket.md](../../docs/esp-screen-micromarket.md).
Тип машины в базе — `micromarket_screen`; каталог ей задаёт владелец из
веб-админки, номер ячейки = `inventory.motor_id` (10–99).

## Чем отличается от соседних прошивок

| | esp-relay | esp-serial | **esp-screen** |
|---|---|---|---|
| Как узнаёт об оплате | MQTT от брокера SmartVend | команда с планшета по USB | сам опрашивает `complete-order` по своему `orderid` |
| Витрина | нет (QR на корпусе) | планшет | **экран платы** |
| Сеть | Wi-Fi/GSM | нет | Wi-Fi/GSM |
| MQTT | да | нет | **нет** — устройство само создало заказ и знает его номер |

Каркас переносится из [esp-pulse](../esp-pulse/): драйвер замка,
provisioning-портал, внешний watchdog, статусный LED. MQTT-подписка не
переносится.

## Железо

ESP32-S3 с 8 МБ PSRAM и 16 МБ флеша, экран по QSPI, ёмкостный тач.

**Проверять на каждой новой плате до всего остального:**

```
espefuse.py --port /dev/ttyACM0 summary | grep -E "SECURE_BOOT_EN|SPI_BOOT_CRYPT_CNT"
```

Нужны `SECURE_BOOT_EN = False` и `SPI_BOOT_CRYPT_CNT = 0`. Плата с прожжённым
secure boot примет только образ, подписанный чужим ключом — своя прошивка на неё
не встанет никогда, и откатить это нельзя. Одна такая уже приезжала.

## Сборка и прошивка

```
. ~/esp/v5.5.1/esp-idf/export.sh
idf.py set-target esp32s3          # только при первой сборке
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

Порт — `/dev/ttyACM0`: у платы родной USB-JTAG, отдельного USB-UART-моста нет,
и консоль настроена на него (`CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG`). По той же
причине `esptool.py` иногда не грузит stub — тогда `--no-stub`.

Версия проекта задаётся в `CMakeLists.txt` (`PROJECT_VER`) и уезжает в
`device_ping` как `p_app_version`. **Префикс `screen-` обязателен**: по нему
панель отличает эту машину от планшета, который шлёт чистый semver.

## Разделы

`partitions.csv`, 16 МБ:

| раздел | размер | зачем |
|---|---|---|
| `nvs` | 20 КБ | номер аппарата, секрет из `device-provision`, Wi-Fi-креды |
| `ota_0` / `ota_1` | по 4 МБ | LVGL со шрифтами и TLS растут быстрее, чем прошивка реле |
| `storage` | 1 МБ | кэш каталога (~110 байт на позицию); переживает OTA |

## Грабли этой панели

Все три выглядят одинаково — чёрный экран без единой ошибки в логе.

**Команды идут по четырём линиям, а `esp_lcd` шлёт их по одной.** Главная и
самая дорогая. Панель ждёт инициализацию в виде `cmd 0x02` + 24-битный адрес
(номер команды), и то и другое по четырём линиям —
`SPI_TRANS_MULTILINE_CMD | SPI_TRANS_MULTILINE_ADDR`. `esp_lcd_panel_io_spi`
кладёт команду в фазу данных и в quad-режиме шлёт её по одной линии; выставить
multiline для команды через его API нельзя. Панель молча не принимает
инициализацию. Поэтому вместо `esp_lcd_panel_io_spi` здесь свой тонкий слой —
[panel_qspi.c](main/panel_qspi.c), повторяющий `Arduino_ESP32QSPI`. Пиксели, в
отличие от команд, идут наоборот: команда и адрес по одной линии, данные по
четырём (`SPI_TRANS_MODE_QIO`).

**Таблица инициализации называется не своим именем.** Нужна
`axs15231b_180640_init_operations` из Arduino_GFX — та, что по названию для
панели 180×640. Именно её библиотека ставит по умолчанию, и только на ней эта
плата оживает. Встроенная таблица компонента Espressif и таблицы `320480 type1`
и `type2` дают чёрный экран. Перевод таблицы в свой формат —
[init_180640.inc.h](main/init_180640.inc.h).

**Кадр уходит кусками по 32 КБ.** `spi_bus_get_max_transaction_len` отдаёт 32768
байт независимо от `max_transfer_sz`. Кадр 320×480×2 — это 300 КБ, десять
кусков, и CS должен оставаться прижатым на всё время: поэтому им управляем сами
(`spics_io_num = -1`), как и рабочая библиотека. Полный кадр уходит за ~15 мс.

**Только полная перерисовка.** В QSPI-режиме панель не принимает окно по
вертикали (`RASET` не шлётся вовсе), поэтому LVGL заведена в
`LV_DISPLAY_RENDER_MODE_FULL`, а буфер лежит в PSRAM: 300 КБ во внутренней
памяти не найти, и она нужна TLS в момент оплаты.

**Порядок байт обратный.** LVGL складывает RGB565 младшим байтом вперёд, панель
ждёт наоборот — перед отправкой кадр разворачивается `lv_draw_sw_rgb565_swap`.
Без этого красный приезжает синим.

## Как это выяснилось

Прямой перебор настроек не помог — все варианты возвращали `ESP_OK` и не
показывали ничего. Помогла эталонная прошивка: сборка примера
[me-processware/JC3248W535-Driver](https://github.com/me-processware/JC3248W535-Driver)
на Arduino_GFX зажгла экран на этой же плате за пять минут. После этого разница
между рабочим и нерабочим стеком свелась к чтению двух файлов —
`Arduino_ESP32QSPI.cpp` и `esp_lcd_panel_io_spi.c`.

Вывод на будущее: когда панель молчит, первым делом стоит поднять её заведомо
рабочей библиотекой, а не перебирать параметры вслепую.

## OTA-потоки не смешивать

В репозитории уже три: планшет (`v*`), esp-relay (`relay-v*`), esp-pulse
(`pulse-v*`). Четвёртый — `screen-v*`. Разделены только префиксом тега и именем
ассета; смешение однажды погасило обновления всему парку планшетов.
